# 领域资料

鱼类通过集鱼槽、155 米轨道提升、无人车和运鱼船越过高坝，运输箱交接数量与增殖鱼苗放流数据分开计量。

## 范围与来源

服务覆盖一条鱼批次从集鱼槽收集、站点分拣、轨道提升、陆运、船运到放流点的逐段核验，以及放流后回捕调查的成效关联：

- **逐段守恒**：每段交接登记发出/接收数量与运输箱清单。短少必须由经确认的死亡记录或重新分拣记录销账；未销账的批次保持 BLOCKED，不能继续向下游流转。
- **死亡与重分拣双签**：先登记 PENDING，由监督人员确认 CONFIRMED 后才影响账面；REJECTED 不扣减。设备故障独立登记并可与死亡关联，零死亡故障也留痕。
- **来源口径**：`origin=WILD` 为天然过坝野生鱼，`origin=HATCHERY` 为增殖站鱼苗。野生鱼过坝放流是保护成效但**不计入增殖放流成效**；增殖成效只统计标记（耳石 OTOLITH / 荧光 FLUORESCENT / PIT 等）命中的回捕（MATCHED）。无标记或标记编码查无此批的回捕一律 UNMATCHED，不归属任何放流批次。
- **追溯**：`GET /v1/lots/{lot_ref}/trace` 汇总每段交接的守恒结果、站点死亡与重分拣、设备故障、放流水体与坐标、标记、放流后数月的调查回捕证据，以及账面恒等式是否闭合。

## 数据约定

`contracts/entities.json` 保存交换字段与规则；`fixtures/example.json` 是不含真实身份的交换样例。
来源编号（lot_ref、container_ref、mark_code 等）是提交方对同一记录的识别符。运行时持久化文件由 `DATABASE_PATH` 决定；时间字段使用带时区偏移的 ISO 8601 字符串。

数据库表结构保存在 `internal/store/migrations/`（`001_bootstrap.sql`、`002_domain.sql`），由服务进程内嵌并在启动时自动应用；也可用 `cmd/migrate`（`make migrate`）单独预热。名录表 `species` 预置了金沙江上游常见本土鱼类（短须裂腹鱼、长丝裂腹鱼、细鳞裂腹鱼、四川裂腹鱼、鲈鲤、长薄鳅、岩原鲤），登记批次时不做外键强制，以免新物种无法录入。
